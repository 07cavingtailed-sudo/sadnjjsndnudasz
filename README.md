# gdbot — ИИ, который сам учится проходить Geometry Dash

Бот играет в Geometry Dash сам: делает тысячи попыток, запоминает, что работает,
и в итоге собирает последовательность нажатий, которая проходит уровень целиком.
Цель — **Skeletal Shenanigans**.

Внутри:

- **симулятор** физики в духе GD (куб, корабль, шар, волна, шипы, блоки, орбы, пады,
  порталы гравитации/режима/скорости) — ~600 000 тиков в секунду, чтобы учиться быстро;
- **генератор уровней** с доказанной проходимостью и бенчмарк‑«демон» на 2 минуты;
- **четыре алгоритма обучения**: beam‑поиск, генетический поиск по нажатиям, CEM, PPO;
- **мост к настоящей игре**: захват экрана, чтение прогресс‑бара, нажатия скан‑кодами;
- CLI, конфиги и 59 тестов.

## Главная идея

Geometry Dash **детерминирован**: одни и те же нажатия в одни и те же кадры дают
один и тот же забег. Значит, «выучить уровень» — это найти *ленту нажатий*
(по биту на кадр: держу / не держу) и никогда не ломать уже работающую часть.

Одна «реактивная» нейросеть сложный демон не пройдёт: в двухминутном уровне
~7000 кадров, и одна ошибка на любом из них — смерть. Поэтому здесь два вида
обучения, и у них разные роли:

```
        ┌──────────────── реактивная политика (CEM / PPO) ────────────────┐
        │  смотрит на препятствия впереди и жмёт; обобщается на новые      │
        │  куски уровня → предлагает, как играть дальше                    │
        └──────────────────────────────┬───────────────────────────────────┘
                                       │ предложение
                                       ▼
  уровень ─► секции ─► ┌───── поиск по ленте нажатий ─────┐ ─► проверенная ─► следующая
             1..N      │ симулятор: beam-поиск по         │    лента секции    секция
                       │ состояниям (полный перебор с     │         │
                       │ дедупликацией)                   │         │ застряли?
                       │ игра: генетика, правит только    │ ◄───────┘ откат на секцию
                       │ кадры перед местом смерти        │   назад, решаем обе вместе
                       └──────────────────────────────────┘
                                       │
                                       ▼
                    вся лента ─► N повторных прогонов ─► пройдено
```

- **Куррикулум — вперёд по секциям.** Секция *k* решается из того состояния,
  в котором игрока *реально* оставляет проверенное решение секций 1..k−1.
  Если секцию решить нельзя (обычно предыдущая «передаёт» игрока с плохой
  скоростью), бот откатывается на секцию назад и решает обе вместе.
- **Генетика бьёт туда, где умер**: у каждого потомка одна точечная правка
  (сдвиг нажатия, вставка, удаление, флип) рядом с местом смерти. Если прогресс
  стоит, правки уходят всё дальше назад: часто смерть «готовится» раньше —
  например, отрыв на кадр позже приводит к падению в конце ямы.
- **Сдвиг суффикса.** В цепочке орбов ранний удар по орбу *k* требует раннего
  удара и по орбу *k+1*. Любая одиночная правка делает забег хуже, поэтому
  поиск, принимающий только улучшения, застревает навсегда (так и было: плато
  на 7.6%). Оператор сдвигает нажатие *вместе со всеми последующими*, сохраняя
  интервалы, — ровно то связанное движение, которое нужно цепочке.

## Что измерено

Все цифры получены на этой машине и воспроизводятся командами из правого столбца.

| Эксперимент | Результат | Команда |
|---|---|---|
| Beam‑поиск, 2‑минутный демон‑бенчмарк | **пройден** за 8 с (684 тыс. состояний), 3/3 чистых прогона | `gdbot solve -c configs/sim.json` |
| Правила настоящей игры (без сохранения состояния), тот же демон | **пройден** за 10 033 попытки, 3 отката, 3/3 чистых прогона (до раннего отката из тупиков было 26 770) | `gdbot solve -c configs/sim.json --blackbox --pretrain 20` |
| Правила настоящей игры, уровень средней сложности | **пройден** за 2 316 попыток, 3/3 | — |
| CEM, тренировочный уровень | политика проходит уровень на **100%** | `gdbot train --level tutorial` |
| PPO (torch), тренировочный уровень | все 4 сида проходят первое препятствие к 15–18 обновлению, 3 из 4 доходят до 56.9% | `pytest tests/test_ppo.py` (первое препятствие) |
| Точность часов тика (в контейнере, не на игровом ПК) | в среднем 0.01 мс, p99 1.2 мс при длине тика 16.7 мс | — |

В режиме «правила настоящей игры» симулятор урезан до того, что даёт игра:
нельзя сохранить/восстановить состояние и начать с середины — только «сыграй
эту ленту с начала и скажи, докуда дошёл». Это прямая проверка алгоритма, который
будет играть в настоящую GD.

## Установка

```bash
pip install -e .              # ядро: только numpy
pip install -e '.[game]'      # на ПК с игрой: mss, opencv, pynput
pip install -e '.[torch]'     # по желанию: PPO
```

## Быстрый старт в симуляторе

```bash
gdbot show  --level skeletal_proxy                 # что за уровень
gdbot train --level tutorial                       # учим политику (CEM)
gdbot solve -c configs/sim.json                    # проходим демон-бенчмарк
gdbot solve -c configs/sim.json --blackbox         # то же по правилам настоящей игры
gdbot play  -c configs/sim.json --runs 3           # переигрываем найденную ленту
gdbot generate my_level --chunks 20 --difficulty 0.8 --out my_level.json
```

Результаты сохраняются в `runs/<имя>/`: `best.tape.json` (лента), `macro.json`
(нажатия по кадрам), `policy.policy.npy` (веса), `log.jsonl` (весь ход обучения).

## Настоящая игра: Skeletal Shenanigans

**В игре:** выставьте фиксированный FPS и тот же `tick_rate` в конфиге (по
умолчанию 60); включите прогресс‑бар (прогресс бот читает именно с него) и
авто‑рестарт после смерти; выключите practice mode; окно игры не двигайте.

```bash
# 1. Разметить экран: скриншот + живые показания прогресса и сетки препятствий
gdbot calibrate -c configs/skeletal_shenanigans.json
#    -> впишите capture.play_area и capture.progress_bar в конфиг

# 2. (по желанию) Записать свои попытки — лучшая станет стартовой точкой
gdbot record -c configs/skeletal_shenanigans.json --attempts 5

# 3. Учиться до прохождения (Ctrl+C можно в любой момент — прогресс на диске)
gdbot solve --game -c configs/skeletal_shenanigans.json --seed-tape human

# 4. Проверить, что лента проходит стабильно
gdbot play --game -c configs/skeletal_shenanigans.json --runs 5
```

Как бот видит игру:

- **Прогресс** — по заполнению прогресс‑бара. Это и сигнал обучения, и детектор
  смерти (бар откатился к нулю), и детектор финиша. Шаблоны и OCR не нужны.
- **Кадр 0 попытки** — по резкой смене картинки, когда камера прыгает в начало
  уровня. Это точность ±1 кадр; по бару было бы ±12 кадров: в начале
  двухминутного уровня бар ещё не заполнил и первого пикселя.
- **Нажатия** — скан‑кодами через `SendInput` на Windows и `/dev/uinput` на Linux.
  Обычные «виртуальные» нажатия игры, читающие raw input, часто игнорируют.

## Честно об ограничениях

- **Время — главный барьер.** Настоящая игра не умеет сохранять состояние, поэтому
  каждая попытка заново проигрывает уже пройденную часть. На 2‑минутном
  бенчмарке это вышло **~217 часов** игры при 60 fps (10 033 попытки). Больше
половины первоначальных попыток уходило на тупики — секции, куда префикс
приводил игрока в безнадёжном состоянии; ранний откат сократил это с ~535 ч. Сократить можно:
  своими записанными попытками (`--seed-tape`) и чекпоинтами practice mode. Второе
  **не реализовано**: оно зависит от того, как именно игра восстанавливает
  состояние на чекпоинте, а проверить это здесь нельзя.
- **Точность по кадрам.** Захват экрана и эмуляция клавиатуры дают небольшой
  разброс. Лента, выученная на настоящей игре, выучена *вместе* с этим разбросом:
  хрупкие тайминги отсеиваются сами. Но участки с окном ровно в один кадр могут
  срываться, и `gdbot play --runs N` показывает, как часто. Для гарантированно
  чистого прогона ленту можно выгрузить (`gdbot export-macro`) в виде списка
  нажатий по кадрам.
- **Зрение препятствий приблизительное** (плотность краёв). От него зависит только
  реактивная политика; поиск по ленте читает один прогресс‑бар.
- **Бенчмарк — не Skeletal Shenanigans.** Это сгенерированный уровень похожей
  структуры и длины. Геометрию настоящего уровня бот читает с экрана.
- **Физика симулятора похожа на GD, но не совпадает побитово.** Поэтому ленту
  из симулятора в игру не переносят: в игре бот учится заново, а симулятор
  нужен для предобучения и отладки.
- Прохождение ботом — не ваше прохождение: не выдавайте его за легитное.

## Как устроен код

```
gdbot/
  sim/            физика, уровни, генератор с доказанной проходимостью
  agents/         beam.py · ga_tape.py · cem.py · policy.py · ppo.py
  env/            общий интерфейс «попыток»: симулятор и настоящая игра
  vision/         прогресс-бар, детектор смерти/финиша, сетка препятствий
  capture/        захват экрана (mss)
  inputs/         нажатия: SendInput / uinput / xdotool / pynput
  features.py     единый вектор признаков для симулятора и игры
  solver.py       куррикулум: секции, откаты, проверка
  record.py       запись попыток человека
  macro.py        статистика и экспорт ленты
  cli.py          команды gdbot
configs/          sim.json · skeletal_shenanigans.json
tests/            59 тестов
```

## Тесты

```bash
pip install -e '.[dev]' && pytest        # ~30 с; тест PPO пропускается без torch
```

Среди тестов есть регрессионные на каждую ошибку, найденную при разработке:
снапшот на границе фрагмента, порталы, задним числом ломавшие проверенный
фрагмент, «храповик» сигмы в CEM и плато на цепочке орбов.
